# meal-bot

Бот заказа питания (MAX) на Python: роутеры, SQLite, импорт студентов из Excel, QR-метки, уведомления.

## Структура
- `run.py` — точка входа
- `bot/` — маршруты (user, staff, admin), клавиатуры, FSM
- `core/` — БД, сервисы, Excel-импорт, QR, уведомления
- `config.py` — настройки из переменных окружения
- `data/init_db.py` — инициализация схемы БД

## Установка
```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # заполните MAX_BOT_TOKEN
```

## Запуск
```bash
python data/init_db.py   # создать БД
python run.py
```

> `.env` не коммитится (см. `.gitignore`). Реальные токены не должны попадать в репозиторий.

## Схема выдачи питания (общий QR + подтверждение сотрудником)
1. Администратор один раз печатает общий QR (кнопка «🖨 QR для раздачи» или `/qr`) и вешает на раздачу.
2. Сотрудник нажимает «▶️ Начать выдачу» — до конца суток (по `BOT_TZ`) запросы приходят ему.
3. Студент сканирует QR и нажимает «Подтвердить» — права резервируются, сотруднику приходит
   «Успешно! Иванов И., 28-143. Обедов к выдаче: N».
4. Сотрудник нажимает «Подтвердить» — только после этого выдача пишется в `meals_log`.
   Без подтверждения права возвращаются студенту через `MEAL_CONFIRM_TIMEOUT_MIN` минут.
5. На сутки у студента одно право; «🎁 Угостить друга» создаёт одноразовую ссылку-подарок
   (сумма прав за сутки не растёт, подарки видны на листе «Подарки» в Excel-отчёте).

Код: `core/meals.py` (права, запросы, подарки), `bot/routers/meal.py` (сценарий в чате).
Личные QR и рассылка отключены; на время пилота работает запасной режим `LEGACY_QR_ENABLED=1`
(сканирование личного QR сотрудником тоже списывает право; ручного ввода кода больше нет). Параметры — в `.env.example`.
